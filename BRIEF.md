# Daniyal Portfolio 2026 — Evidence in Motion

## Purpose

Create a personal portfolio for design juries, technical collaborators, ambitious founders, and teams hiring an AI product builder. The visitor should leave believing that Daniyal does not wrap models in generic interfaces: he builds memory, tools, safeguards, interaction, and observable proof as one system.

“Awwwards quality” is the acceptance bar for craft, not an award claim.

## Art direction

- Visual thesis: liquid-metal identity opens a precise editorial system where technical proof becomes legible.
- Hero focal asset: owner-supplied monochrome film, D mark, and Daniyal wordmark, followed by one high-contrast proposition plate that maps memory → action → evidence.
- Type: Geist grotesk with oversized editorial headlines, readable support copy, and compact operating labels.
- Palette: carbon, paper, ink, silver, and one signal cobalt reserved for state, focus, route, and primary action.
- Motion: GSAP + ScrollTrigger with one Lenis instance; restrained masks, shallow parallax, scroll scrubs, a CSS perspective tunnel, and deliberate handoffs.
- Realtime boundary: no Three.js scene or spatial camera world. A single bounded SilkWaves WebGL field is allowed as a decorative evidence surface, with a CSS fallback and reduced-motion still frame.
- Asset provenance: identity media is owner-supplied; project claims link to public source or are explicitly labelled interaction proof.

## Journey

1. Arrival — identify Daniyal and the AI/product/interaction position immediately.
2. Thesis — explain remember → act → verify in one editorial statement.
3. Selected work — frame the portfolio honestly as independent R&D and expose a one-viewport visual route to all three proof types.
4. JARVIS — show a persistent operating layer, public architecture evidence, and exact source receipts.
5. HELIX — demonstrate a keyboard-operable simulated recovery path with a visible proof boundary.
6. QADAM — show real public-release product footage, reproducible benchmark evidence, public methodology, and exact source receipts.
7. Method — explain the operating route and capabilities without interrupting the work sequence.
8. Active Field — expose four additional public builds through a responsive 2D laboratory.
9. Operator profile — connect THINK / BUILD / PROVE to the author.
10. Private inquiry — end with one high-contrast project-brief action and a quiet footer.

Direct chapter navigation must preserve access to Work, Method, About, and Contact without forcing the full long-form scroll.

HELIX and QADAM are separated by an unnumbered paper handoff: recovery keeps an operation alive; evidence makes its claims trustworthy. This beat changes the scene without adding navigation complexity.

## Acceptance requirements

- Complete semantic page with one H1, logical headings, real links, private contact flow, and visible focus.
- Mobile, touch, narrow-landscape, reduced-motion, save-data, no-JS, loading, disabled, error, and success states remain usable.
- One smooth-scroll owner; animation resources clean up; hero video pauses offscreen and is absent under reduced motion.
- No invented clients, testimonials, awards, adoption metrics, benchmarks, or production URLs.
- Production typecheck, source verifier, build, metadata routes, and browser QA pass before handoff.
