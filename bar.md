# Rendered craft bar — Lusion comparison

Reference: the live `https://lusion.co/` homepage at 1440×900 plus the owner-supplied desktop captures. These are comparison evidence, not a source for copied assets, identity, layout, or wording.

1. **One unmistakable focal event per viewport.** At least two thirds of the frame belongs to one dominant image, typographic statement, or interaction; navigation and metadata remain supporting layers.
2. **The reading order is visible in under three seconds.** Each frame uses no more than three competing type tiers, and the eye reaches identity → proposition → next action without crossing dense UI furniture.
3. **Scroll changes the scene, not only the element position.** Every major handoff produces a perceptible state change—material to paper, thesis to evidence, fault to recovery, or proof to invitation—with one leading motion and restrained supporting stagger.
4. **Long-form pacing alternates pressure and release.** Dense proof scenes are followed by generous editorial air or a full-frame reset; no two adjacent chapters repeat the same composition, contrast, or motion grammar.
5. **Evidence is staged as a visual payoff.** A flagship chapter must expose its constraint, built mechanism, and proof boundary within one viewport before secondary details ask for reading.
6. **Chrome stays quieter than content.** Persistent navigation, progress, cursors, labels, and frames never compete with the active focal plate; they exit or simplify when a scene needs the full visual field.
7. **Mobile is re-composed, not scaled down.** At 390×844 there is one focal subject, one readable action, zero horizontal overflow, no fixed-control collision, and all scroll-owned content resolves to a complete static state under reduced motion.

## Jarvis Project Dimension — approval bar

Reference: the rendered first viewport of the existing `/work/jarvis?embed=universe` case study at 1920×1080. The universe representation must derive from this project frame, not from unrelated space imagery.

1. **The product reads before the label.** A visitor can identify a website / AI operating interface from the full hero frame, browser-like signal panel, and operational UI fragments even if the floating `JARVIS` metadata is hidden.
2. **The real preview owns the frame.** The 16:9 project preview is the largest meaningful object at every focus endpoint; no decorative object approaches its screen area or contrast.
3. **Three authored depth planes remain legible.** Cropped interface fragments cross the near foreground, the complete case-study hero occupies the midground, and only quiet data rails / signal traces sit behind it.
4. **Every supporting object has project provenance.** The title crop, `03 / 03` receipt, operation trace, cobalt signal lines, and grid frame are taken from or directly encode the existing JARVIS hero and operating path.
5. **Assembly has one direction.** Scroll brings separated fragments toward the main preview, reduces yaw and depth offsets, and resolves into one flat 16:9 rectangle without orbiting, spinning, or arbitrary sculpture motion.
6. **The camera ends on a matchable frame.** At entry, the preview is front-facing, centered, 16:9, and composed from the exact first viewport used by the embedded `/work/jarvis` page, so the DOM takeover can happen without a conceptual cut.
7. **Chrome stays subordinate.** Universe labels, particles, route lines, and distant projects remain dim enough that the JARVIS interface is the first and last visual read during its focus interval.
