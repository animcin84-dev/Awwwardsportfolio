# Awwwards readiness — audit and roadmap

There is no honest way to guarantee an Awwwards win. The goal is to maximize the probability by making the portfolio memorable, coherent, useful, fast, and demonstrably custom-built.

## Creative concept

**An evidence operating system:** projects rotate from signal to context to proof; the scroll behaves like a system that remembers, acts, and verifies.

This concept ties the liquid-metal opening, repository atlas, infinite artwork field, operating-method typography, capability theatre, observable operation trace, About console, and final contact signal into one visual and interaction language.

## Baseline audit

### Strong / preserve

- Distinctive liquid-metal identity, wordmark, carbon/paper/cobalt palette, and oversized editorial typography.
- Three deep flagship cases with honest evidence boundaries and working proof interactions.
- Clear product thesis: memory → action → evidence.
- Existing route transition, cursor language, accessibility foundations, reduced-motion path, and mobile hero derivative.

### Problems that were lowering perceived quality

- The 3000svh Universe felt like a detached technology demo, dominated the page, and kept a GPU-heavy 3D runtime alive.
- Primary navigation pointed at homepage anchors, so the site lacked clear, shareable top-level chapters.
- Only three repositories had a designed discovery path even though the public profile contains fourteen builds.
- Method, capability, Active Field, About, and Contact used weaker or click-dependent compositions after a strong opening.
- The hero video attached aggressively and could compete with first-paint and later GPU work.

### Missing opportunities

- One memorable, project-specific discovery interaction.
- A designed Work index and local portrait route for every public repository.
- Automatic capability storytelling for visitors who never click an accordion.
- A deliberate mobile interpretation of the signature systems.
- A compact contact conversion moment instead of another full-screen form chapter.

## Implemented high-impact changes

- **P1 / Signature:** replaced Universe with a 14-project rotating scroll atlas. Project names stay on the left, visual plates rotate on the right, and every image opens a local `/work/...` page.
- **P1 / Navigation:** converted Work, Method, About, and Contact into independent routes; the vertical rail now navigates pages instead of homepage coordinates.
- **P1 / Memory–Action–Evidence:** adapted the supplied infinite canvas with its artwork set and a three-state center-title transition.
- **P1 / Method:** adapted the supplied scroll-text motion into HOLD CONTEXT → MAKE THE MOVE → PROVE THE RESULT, with readable sentence fragments around each state.
- **P1 / Protocol:** removed the second project carousel after a duplicate-content audit and replaced it with a six-stage observable Operation Trace: frame → restore → constrain → execute → verify → return.
- **P1 / Storytelling:** rebuilt the capability area as an automatic theatre rather than hidden accordion copy.
- **P1 / Finish:** rebuilt About as an operating console and Contact as a compact two-column invitation with a separate epilogue.
- **P1 / Performance:** removed the Three.js Universe from the homepage runtime, deferred video attachment, kept the poster as the stable first frame, used the mobile derivative, and faded the film in only once playback actually starts.
- **P1 / Motion performance:** halved atlas scrub ownership from 28 triggers to 14, moved all 18 infinite-canvas images with one shared plane instead of 18 frame tweens, removed large animated blur/backdrop layers, stopped the cursor RAF when settled, and eliminated the always-running offscreen marquee. Local production sampling now reports zero actually running offscreen CSS animations at top, mid-page, and footer after settling.
- **P2 / Coverage:** created designed local project portrait pages for all fourteen public repositories while preserving the deeper JARVIS, HELIX, and QADAM case studies.

## Remaining launch gates before an award submission

### P0 — required

- Configure and test a durable production contact webhook; do not submit with an ephemeral or unverified inbox.
- Run real-device Safari iOS and Chrome Android checks for the long scroll sequences, drag threshold, keyboard/focus order, video decode, memory pressure, and reduced motion.
- Capture production Web Vitals on the deployed origin. Target stable LCP/CLS/INP rather than a synthetic score screenshot.

### P1 — highest remaining creative value

- Replace the generative project plates for at least the six strongest builds with real, art-directed interface footage or repository-derived screenshots. Keep the plate system as framing, not as a substitute for product evidence.
- Add verified outcome material where the owner can prove it: users, evaluation, time saved, competition result, or shipped status. Do not invent numbers.
- Give the strongest non-flagship projects one unique proof interaction each, prioritizing AqylShahar, Consent OS, Ustaz AI, vtor.ai, and Gargantua.
- Curate the final project order after deciding the target audience. Fourteen projects show range; the first six must show the exact work Daniyal wants next.

### P2 — submission polish

- Produce a 30–45 second entry reel showing the hero, atlas rotation, infinite canvas, method transition, Operation Trace, About console, and epilogue without cuts that hide performance.
- Finalize canonical production URL, social card, favicon/manifest, structured data, and case-specific share images.
- Run one final keyboard, focus, contrast, forced-colors, reduced-motion, 404, direct-link, refresh, and Back-button audit after deployment.
- Add optional sound only if it reinforces the operating-system concept, starts muted, and has an obvious control. The site does not need sound to be award-worthy.

## Quality model after this round

- **Design:** strong, coherent art direction with a higher portfolio-wide floor.
- **Creativity:** now has two describable signature moments: the rotating repository atlas and the infinite Memory/Action/Evidence field.
- **Usability:** clearer top-level routes, local project destinations, smoother state changes, automatic demos, preserved manual controls, and zero horizontal overflow at the measured 390px mobile viewport.
- **Content:** broad repository coverage; real product media and verified outcomes remain the largest opportunity.
- **Development:** lighter homepage GPU profile, one native-scroll motion system, demand-driven cursor animation, and no continuously running offscreen CSS animation in sampled states; real-device production profiling remains mandatory.
